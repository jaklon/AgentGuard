## Changes

- Added the mainnet explorer button, official explorer logo, accessible label,
  new-tab protection, and responsive layout.
- Fixed font variable scope so the application's Inter font actually applies.
- Recheck network, selected wallet account, and contract code before payment or
  policy signing; reject stale wallet sessions instead of signing for another account.
- Enforce request size against actual streamed bytes, including requests without
  Content-Length, before JSON parsing.
- Updated FastAPI, Starlette, and Python test dependencies after dependency scanning.
- Exact balance questions now use fresh RPC data without inference or history scans.
  General assistant context is fetched concurrently; only the latest five payments,
  top five recipients, and four bounded conversation messages enter the prompt.
  Output budget is reduced from 640 to 320 tokens.
- Assistant snapshot loading skips unused wallet-wide explorer activity. Failed
  live refreshes are not presented as fresh data. Incomplete hidden reasoning is removed.
- Added regression coverage for wallet signing, streamed request size, assistant
  fast-path/network checks, contract permissions, limits, expiry, and withdrawals.

## Validation and limitations

- Python API/guard suite: 29 passed.
- Wallet safety tests: 4 passed; production Next.js build and TypeScript checks passed.
- Hardhat contract tests: 8 passed. Contract source and deployed contracts were not modified.
- Browser smoke: landing at 1440px/390px, logo/link, login/dashboard/payment routes,
  all eight dashboard navigation items, and payment-link/QR generation passed with
  no uncaught JavaScript errors. Backend was not running in this browser test;
  unavailable API requests are not evidence of successful live wallet integration.
- Frontend dependency audit: no known vulnerabilities reported.
- Python environment dependency audit: no known vulnerabilities reported after updates
  (local application packages are not in the public advisory database).
- Hardhat development dependency audit still reports 37 findings (16 high, 7 moderate,
  14 low). npm's proposed remediation includes a breaking Hardhat/toolbox migration.
  Do not run `npm audit fix --force` against deployment tooling without separately
  migrating and testing scripts/plugins. This tooling is not bundled in the web runtime;
  findings still require follow-up. Keep deployer keys out of CI and untrusted scripts.

This was a source review, automated regression testing, dependency scanning, and
local browser smoke testing, not an independent security audit or a guarantee of
all features. Production wallet signing, mainnet payments, Docker image/OS scanning,
explorer source verification, and production Qwen latency were not tested.
Actual response time depends on RPC latency and the server's model/CPU; no measured
production speedup is claimed. General model responses remain non-streaming.

## Rollout

On the existing Ubuntu deployment, after reviewing local changes:

```sh
cd /srv/agentguard
git status --short
git pull --ff-only origin main
docker compose up -d --build backend frontend
docker compose ps
```

Preserve existing `.env`, database volumes, model files, and network settings. Never
copy the deployer private key into frontend variables or commit it. Check the new
landing-page link, health endpoint, wallet connection, and an assistant balance
question after rollout. Existing contract deployment need not be repeated.
